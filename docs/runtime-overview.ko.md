# 연구 세부목표 1. 다중 CXL-PIM 장치를 위한 인메모리 연산 라이브러리 개발

다중 CXL-PIM 장치의 메모리와 연산 자원을 효율적으로 활용하기 위해, 하나의 워크로드를 여러 장치에 나누어 실행하는 PIMLibrary를 개발함. 연산을 분배할 때는 두 가지 사항을 고려해야 함. 먼저 각 장치가 처리할 데이터 범위를 정하고, 해당 장치에서는 PIM의 메모리 내 연산과 NDP 코어의 범용 연산 중 어느 기능을 사용할지 지정해야 함. 이에 따라 응용 프로그램이 연산과 배치 방식을 지정하는 User-level API를 High-level PIM Library에 포함하고, 장치별 메모리 접근과 연산 실행은 Low-level PIM Library가 담당하도록 구성함.

## 1) High-level PIM Library

다중 CXL-PIM 장치의 연산 자원과 메모리를 효율적으로 활용하기 위해 High-level PIM Library를 구현함. 여러 장치가 하나의 워크로드를 나누어 처리할 수 있도록 장치 간 연산 분배와 데이터 통신을 지원함. 개별 장치에서는 PIM과 NDP의 특성에 맞게 연산을 수행할 수 있도록 엔진별 데이터 배치와 연산 스케줄링을 지원함. 또한 연산마다 데이터를 다시 전송하는 비용을 줄이기 위해 가중치와 중간 결과를 장치 메모리에서 재사용할 수 있도록 함.

- **Data Management**
  - 데이터를 사용하는 기간과 갱신 방식에 따라 저장 공간을 관리함. 가중치는 반복 연산이 끝날 때까지 해당 장치에 보관하고, 중간 결과는 이를 입력으로 사용하는 연산이 완료될 때까지 유지함. 값이 자주 바뀌는 데이터에는 고정 크기의 버퍼를 할당하여 필요한 구간만 갱신함. 갱신 전의 값이 후속 연산에도 필요한 경우에는 해당 구간을 독립된 텐서로 복사해 보존함.
  - 동일한 가중치라도 NDP가 행렬을 읽는 순서와 PIM의 각 뱅크가 내적에 사용할 값을 읽는 순서는 다를 수 있음. 이에 따라 응용 프로그램에서 사용하는 행렬의 형상과 값은 유지하면서, 엔진별로 필요한 물리적 배치를 준비할 수 있도록 함. 두 배치를 유지하는 데에는 메모리가 추가로 들지만, prefill과 decode에서 같은 가중치를 사용할 때 단계가 바뀔 때마다 데이터를 다시 변환하는 비용을 줄일 수 있음.

- **Scheduling**
  - 런타임은 한 세션에서 요청한 데이터 전송과 연산을 순서대로 처리함. 연산을 요청받으면 입력 형상과 데이터 형식이 지정한 엔진의 지원 조건에 맞는지 확인함. 예를 들어 PIM은 입력이 한 행이고 bias가 없는 Linear를 지원하며, 여러 행의 입력을 처리하거나 bias를 더할 때는 NDP를 사용할 수 있음. 실행에 필요한 입력 배치와 작업 공간도 함께 확인하며, 필요한 공간이 장치의 scratchpad 용량을 초과하면 실행 전에 오류를 반환함.
  - 앞선 연산의 출력을 다음 연산에서 사용할 때는 런타임이 선행 연산의 완료 여부를 추적함. 예를 들어 PIM projection의 출력을 NDP 덧셈의 입력으로 지정하면, 런타임은 projection이 끝난 뒤 덧셈을 요청하고 덧셈이 끝날 때까지 입력 버퍼를 유지함. 응용 프로그램은 두 연산 사이에 중간값을 호스트로 가져오거나 별도로 대기할 필요가 없음.

- **Multi-Device Communication**
  - 장치 간 통신 방식은 각 장치가 완전한 출력 원소를 계산하는지, 한 원소의 부분합을 계산하는지에 따라 달라짐. Linear의 출력 차원을 나누면 각 장치가 동일한 입력과 서로 다른 가중치 행을 사용하므로 담당한 출력 원소의 계산을 독립적으로 마칠 수 있음. 전체 출력이 필요할 때는 이를 원래 열 순서대로 이어 붙임. 입력 차원을 나누면 각 장치가 내적의 일부만 계산하므로, 같은 출력 위치에 해당하는 부분합을 모두 더해야 함.
  - 현재 장치 간 전송에는 호스트 메모리를 사용함. 여러 장치에 같은 입력을 배포할 때는 원본을 호스트에 한 번만 복사하고 그 사본을 각 장치로 전송함. 부분합을 모을 때는 장치별 결과를 FP32로 읽어 호스트에서 합산한 뒤 목적지 장치에 저장할 때 한 번만 FP16으로 변환함. 이를 통해 합산 전 부분합에서 발생할 수 있는 반올림 오차를 줄임.

## 2) User-level API

응용 프로그램에서 PIM과 NDP의 연산을 호출하고 장치 간 데이터 전송을 요청할 수 있도록 C++ User-level API를 구현함. 사용자는 세션으로 실행 장치를 선택하고, 연산별로 사용할 엔진을 지정함. 한 장치에서 반환한 텐서는 같은 세션의 후속 연산에 전달할 수 있으며, 여러 장치에서 분할 계산한 출력은 장치 그룹의 통신 기능으로 취합함.

- **Device and Data Access**
  - 단일 장치에 연결할 때는 세션을 생성하고, 여러 장치를 사용할 때는 장치별 세션을 하나의 그룹으로 구성함. 사용자는 그룹 내 장치 번호로 세션을 선택한 뒤 해당 장치에 데이터를 올리거나 연산을 요청함. [표 1]에 장치 연결 및 선택에 사용하는 C++ 인터페이스를 정리함.

  **[표 1] 세션 및 장치 그룹 인터페이스**

  | 구분 | 공개 인터페이스 | 기능 |
  |---|---|---|
  | 장치 연결 | `Session::create` | 선택한 Backend에 연결한 C++ 세션을 생성함. |
  | 그룹 구성 | `DeviceGroup::create` | 독립된 디바이스 세션을 하나의 그룹으로 구성함. |
  | 장치 선택 | `DeviceGroup::device` | 그룹 내 장치 번호로 해당 세션을 조회함. |

  - 입력의 형상과 데이터 형식을 지정해 호스트 데이터를 장치 텐서로 전송함. 값을 반복해서 갱신할 때는 버퍼를 한 번 할당하고 [표 2]의 구간 복사 기능으로 변경된 부분만 기록함. 호스트에서 결과가 필요한 경우에는 동기 다운로드로 값을 받거나, 비동기 전송을 요청한 뒤 전송 핸들로 결과를 회수함.

  **[표 2] 메모리 및 데이터 접근 인터페이스**

  | 구분 | 공개 인터페이스 | 기능 |
  |---|---|---|
  | 메모리 할당 | `allocate` | 지정한 형상과 데이터 형식에 맞게 버퍼를 할당하고 0으로 초기화함. |
  | 메모리 조회 | `memory_stats` | 세션에서 사용 중인 디바이스 메모리와 작업 공간의 크기를 조회함. |
  | 데이터 전송 | `from_host` | 호스트 데이터를 디바이스에 올리고 텐서를 반환함. |
  | 데이터 전송 | `to_host` | 디바이스 텐서를 호스트로 복사함. |
  | 데이터 전송 | `to_host_async` | 비동기 다운로드를 요청하고 전송 완료를 확인할 핸들을 반환함. |
  | 버퍼 관리 | `copy_into` | 대상 버퍼의 지정 구간에 원본 텐서의 값을 복사함. |
  | 버퍼 관리 | `snapshot` | 버퍼의 지정 구간을 독립된 텐서로 복사함. |
  | 버퍼 관리 | `clear` | 버퍼의 할당을 유지하면서 전체 값을 0으로 초기화함. |
  | 배치 관리 | `query_layout` | 지정한 텐서 형상과 layout에 필요한 물리적 배치 정보를 조회함. |
  | 배치 관리 | `materialize_layout` | 기존 텐서에 지정한 layout을 추가로 준비함. |
  | 배치 관리 | `prepare_layouts` | 요청한 layout을 모두 갖춘 텐서를 반환하여 반복 연산에 재사용할 수 있도록 함. |

- **Execution Control and Communication**
  - 연산별로 실행 엔진과 입력 layout 정책을 지정할 수 있도록 함. 반복 사용할 가중치의 배치를 미리 준비한 사용자는 준비된 layout만 허용하도록 설정하여 연산 도중 추가 packing이 발생하는 것을 방지할 수 있음. 실행 중에는 텐서나 전송 작업 하나의 완료를 기다리거나, 세션에 요청한 작업 전체의 완료를 확인할 수 있음. 여러 장치의 출력이 필요한 경우에는 [표 3]의 통신 기능에 장치별 결과를 전달하고, 출력 조각의 결합 또는 부분합의 합산을 요청함.

  **[표 3] 실행 제어 및 장치 간 통신 인터페이스**

  | 구분 | 공개 인터페이스 또는 설정 | 기능 |
  |---|---|---|
  | 실행 자원 조회 | `Session::capabilities` | 디바이스 메모리와 scratchpad 용량을 조회함. |
  | 실행 조건 지정 | `OpOptions` | 연산에 사용할 엔진과 입력 layout 준비 정책을 지정함. |
  | 실행 계획 조회 | `Session::query_operation` | 지정한 엔진과 입력 조건에 대해 입출력 layout과 작업 공간 요구량을 확인함. |
  | 상태 조회 | `Event::status` | 연산이나 전송의 대기·실행·성공·실패 상태를 조회함. |
  | 개별 작업 동기화 | `Event::wait` | 해당 작업이 끝날 때까지 기다리고 실행 오류를 확인함. |
  | 결과 동기화 | `Tensor::wait` | 해당 텐서의 값을 생성하는 연산이 완료될 때까지 기다림. |
  | 세션 동기화 | `Session::synchronize` | 해당 세션에 요청한 작업 전체의 완료를 확인함. |
  | 장치 간 복사 | `copy_to` | 지정한 장치에 텐서를 복사하며, 목적지에 있는 텐서는 그대로 사용함. |
  | 입력 배포 | `broadcast` | 같은 입력 텐서를 그룹 내 모든 장치에 배포함. |
  | 출력 결합 | `all_gather_rows` | 분할된 출력 행렬을 열 방향으로 이어 붙여 전체 행렬을 각 장치에 배치함. |
  | 부분합 합산 | `reduce_partials` | 장치별 FP32 부분합을 더한 뒤 FP16으로 변환하여 지정한 장치에 저장함. |

- **Compute API**
  - 행렬–벡터 곱과 Linear projection뿐 아니라 NDP에서 수행하는 정규화, 활성화, 원소별 산술 및 데이터 재배치 연산을 제공함. 사용자는 각 연산이 반환한 텐서를 다음 연산의 입력으로 전달하여 모델의 계산식을 구성함. 예를 들어 FFN의 SwiGLU는 gate projection의 출력에 SiLU를 적용하고 그 값에 up projection의 출력을 원소별로 곱하여 계산함. 입력 차원을 나눈 Linear는 분할 계산의 정밀도를 유지할 수 있도록 장치별 부분합을 FP32로 반환함.

  **[표 4] 공개 연산 목록**

  | 연산 | 공개 인터페이스 | 기능 및 지원 조건 |
  |---|---|---|
  | 행렬–행렬 곱 | `matmul` | NDP에서 두 행렬의 곱을 계산함. |
  | 행렬–벡터 곱 | `matvec` | PIM 또는 NDP에서 행렬의 각 행과 입력 벡터의 내적을 계산함. |
  | Linear projection | `linear` | 입력과 가중치 전치 행렬의 곱을 계산함. NDP는 여러 행의 입력과 bias를 지원하며, PIM은 입력이 한 행이고 bias가 없는 경우를 지원함. |
  | 부분합 계산 | `linear_partial` | 입력 차원을 분할한 Linear의 장치별 부분합을 FP32로 반환함. |
  | 원소별 덧셈 | `add` | 두 입력의 대응 원소를 더함. |
  | 원소별 곱셈 | `mul` | 두 입력의 대응 원소를 곱함. |
  | 상수 곱 | `scale` | 각 원소에 지정한 상수를 곱함. |
  | 정규화 | `rms_norm` | 마지막 축에 대해 RMSNorm을 수행함. |
  | Softmax | `softmax` | 마지막 축에 대해 softmax를 수행함. |
  | 활성화 | `silu` | 각 원소에 SiLU를 적용함. |
  | 형상 변경 | `reshape` | 원소 수를 유지하면서 지정한 형상의 텐서를 생성함. |
  | 전치 | `transpose` | 2차원 행렬의 두 축을 교환함. |
  | 원소 선택 | `gather` | 지정한 인덱스의 원소를 읽어 출력 텐서를 구성함. |

## 3) Backend

Backend는 Low-level PIM Library의 진입점이며, High-level runtime과 장치 사이의 실행 규약을 IBackend로 정의함. 런타임은 먼저 요청한 연산에 필요한 자원과 데이터 배치를 조회하고, 실행 조건을 확인한 뒤 입출력 버퍼를 지정하여 작업을 요청함. 이 과정에서 런타임은 텐서의 형상과 연산 간 의존성을 관리하고, Backend는 실제 할당 영역에 대한 메모리 접근과 연산 수행을 담당함.

- **Capability Query**
  - Backend가 제공하는 정보는 장치 자체의 자원과 개별 연산의 요구사항으로 구분함. 장치 단위로는 디바이스 메모리와 scratchpad 용량, 저장 가능한 데이터 형식을 조회함. 연산 단위로는 선택한 엔진이 요구하는 입출력 layout과 작업 공간 크기를 조회함. 두 조회 모두 메모리 할당이나 데이터 전송을 수반하지 않으므로, 런타임은 피연산자를 준비하기 전에 해당 장치에서 연산을 수행할 수 있는지 판단할 수 있음.

  **[표 5] Backend의 장치 정보 조회 인터페이스**

  | 내부 인터페이스 | 제공 정보 |
  |---|---|
  | `capabilities` | 장치 이름, 디바이스 메모리 용량 및 scratchpad 용량 |
  | `supports_storage` | 지정한 데이터 형식의 저장 가능 여부 |
  | `query_layout` | 논리적 형상과 layout 종류에 대응하는 물리적 배치 정보 |
  | `query_operation` | 요청한 엔진에서의 연산 지원 여부, 입출력 layout 및 작업 공간 요구량 |

- **Memory and Execution Interface**
  - Backend는 디바이스 메모리를 할당한 뒤 해당 영역을 식별하는 핸들을 반환함. 런타임은 복사나 배치 변환을 요청할 때 원본과 대상 핸들을 지정하고, 연산을 요청할 때는 실행 계획과 함께 입출력 핸들을 전달함. Backend는 성공과 실패 모두에서 해당 작업의 버퍼 접근이 끝난 뒤 반환함. 따라서 런타임은 정상 완료한 결과를 후속 연산에 전달할 수 있고, 실패한 경우에도 접근 중인 버퍼를 먼저 해제하지 않고 실행 오류를 보고할 수 있음.

  **[표 6] Backend의 메모리 관리 및 실행 인터페이스**

  | 내부 인터페이스 | 기능 |
  |---|---|
  | `allocate` | 지정한 바이트 크기의 디바이스 메모리를 할당함. |
  | `release` | 할당 핸들에 해당하는 메모리를 해제함. |
  | `reserve_workspace` | 세션에서 반복 사용할 연산 작업 공간을 확보함. |
  | `upload` | 호스트 데이터를 디바이스 메모리로 전송함. |
  | `upload_typed` | 저장할 데이터 형식을 지정하여 호스트 데이터를 전송함. |
  | `download` | 디바이스 데이터를 호스트 버퍼로 전송함. |
  | `copy_region` | 지정한 바이트 범위를 디바이스 버퍼 간에 복사함. |
  | `fill` | 할당 영역 전체를 지정한 바이트 값으로 채움. |
  | `transform` | 원본 layout의 데이터를 대상 layout으로 변환함. |
  | `execute` | 실행 계획과 입출력 버퍼 핸들에 따라 연산을 수행함. |
  | `shutdown` | 장치와의 입출력을 종료함. |
