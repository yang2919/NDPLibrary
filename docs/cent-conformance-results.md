# Native CENT conformance results

The full default boundary sweep passed in both arithmetic modes on all five
validation geometries. Two additional long-K GEMVs passed on the wide geometry.
The table counts distinct test cases. Each case was exported from the real C++
Session/command backend and replayed twice.

| Suite | GEMV cases | PNM Matmul | PNM Linear with bias | Replays | Logical download checks |
| --- | ---: | ---: | ---: | ---: | ---: |
| Boundary | 450 | 210 | 210 | 1,740 | 7,050 |
| Large | 2 | 0 | 0 | 4 | 22 |

The boundary profiles vary C×B, bank row size and GB size. The largest boundary
N was 101 and the largest boundary K was 3,079. In the separate large sweep,
`W[257,4097]` and `W[129,11009]` both exercised final partial tiles and bank
groups. The second shape was chosen to keep long-K coverage within the fixture
memory budget. The initially suggested `W[1025,11009]` remains outside this run.

Every packed weight snapshot matched the independent layout formula including
padding after destination poisoning. In profile mode every observed FP16 download
matched the local emulator. Computing the expected outputs directly from the dense
host inputs also matched all 7,072 downloads including sentinel checks. Each GEMV
fixture reuses its prepared weight and passes PIM output through PNM Add into a
second PIM projection for three A/B/A requests. Allocation counters were checked
after each request and at teardown.

Across random-input downloads, native CENT produced zero differing FP16 download
buffers in these runs. Before FP16 conversion the maximum observed absolute error
against the float64 MAC reference was `4.351139068603516e-06` in the boundary
suite and `7.647275924682617e-05` in the large suite. Each observed accumulator
was checked against a bound scaled by its operand products. Other inputs can
expose the differing reduction orders.

The source fingerprint was `9ac2e163c300caf503eea955ab9f3b051a38fd599c4f1b2c062fbc962458a39e`
for CENT `aim_sim.py` at `4c2aac6ce6aa3ddfe1944fc9c5d656b90d3fc7d2`.
The run used CPU Torch 2.9.1 and Python 3.14.0. Native and ASan/UBSan CTest
builds each passed all 27 configured tests. Targeted corruption checks cover
packed padding, MAC column, output bytes, geometry and malformed wire records.

PNM results cover the library's host-emulated FP32 FMA and Add semantics on
shared replay data. CENT execution coverage applies to its AiM bank, GB, MAC and
latch primitives. The sweep covers finite FP16 inputs and uses the native C++
tests for separate arithmetic and allocator contracts. RVV execution, byte-level
unaligned transfers, nonfinite cross-model conformance, hardware timing and FS
execution are outside the measured coverage.

The boundary and large run reports are generated by the commands in the
[reproduction guide](cent-user-verification.md). The original sweep reports can
also be audited by running `check_outputs.py` on their saved fixtures. This
logical output check was added after the original boundary run and subsequently
incorporated into the sweep runner.
