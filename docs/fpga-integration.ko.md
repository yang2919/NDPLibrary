# PIMLibrary의 VHK158 FPGA 연동

## 1) FPGA 연동을 위한 Backend

PIMLibrary에서 호출한 연산을 FPGA에서 수행하기 위해, Low-level PIM Library에 NDP 커널 요청과 PIM 명령 시퀀스를 구성하고 패킷으로 전달하는 기능을 구현함. 호스트가 연산 순서를 정하고 보드가 각 명령을 채널별로 실행하는 AiMX의 구조를 참고함. 현재 패킷 송수신은 Unix 소켓 기반 참조 구현에서 동작함. VHK158 통합 보드에서는 외부 호스트가 PCIe를 통해 NDP 커널 실행과 PIM 연산을 모두 요청하는 방식을 목표로 함.

- **PCIe로 전달할 요청과 응답**
  - 통합 보드 연동을 위해 호스트와 FPGA가 주고받을 메시지에 요청 종류와 식별 정보를 포함하도록 설계함. 요청 종류는 메모리 읽기·쓰기와 NDP·PIM 연산 실행을 구분하며, 세션 번호와 요청 순번은 호스트가 보드의 응답을 원래 요청과 대응시키는 데 사용함.
  - 메모리 전송에는 보드에서 읽거나 쓸 주소와 바이트 수가 필요함. 쓰기 요청에서는 해당 주소에 저장할 데이터를 보내고, 읽기 요청에서는 지정한 범위의 데이터를 돌려받음. 이미 보드에 배치한 가중치나 중간 결과는 연산 요청에 버퍼 주소만 지정하여 재사용함.
  - 연산 실행 요청에는 어떤 계산을 수행하고 결과를 어디에 기록할지 명시함. NDP에는 커널 식별자, 입출력 버퍼 주소, 행렬 차원 등 커널 인자를 전달함. PIM에는 대상 채널·뱅크, 피연산자 위치, 처리 범위와 함께 데이터 이동·누산·결과 기록에 필요한 명령을 실행 순서대로 전달함.
  - 연산 완료 응답에는 요청 식별 정보와 성공 여부를 담고, 실패한 경우 오류 정보를 제공함. 호스트가 후속 연산에서 결과를 사용할 수 있도록, 성공 응답은 보드가 계산을 마치고 출력 버퍼에 결과를 기록한 시점을 의미함.

- **FPGA 초기 설정 및 커널 적재**
  - NDP 보드의 초기 구동 스크립트는 Xilinx System Debugger(XSDB)를 사용함. JTAG으로 보드에 연결한 뒤 `device program`으로 Versal 구성 이미지(PDI)를 프로그래밍하고, `mwr -bin -file`로 RISC-V 커널 바이너리를 보드 DDR에 기록함. 이후 코어의 리셋을 해제해 커널을 실행하고, `mrd -value`로 커널이 DDR에 기록한 완료 상태와 실행 결과를 읽음.

- **PCIe를 통한 NDP·PIM 실행 요청**
  - Backend는 NDP 연산에 대해 실행할 커널과 입출력 버퍼 주소, 연산 인자를 준비함. 현재 NDP 프로토타입은 보드 내부의 Cortex-A72에서 공유 DDR의 큐를 통해 커널을 호출함. 통합 보드에서는 외부 호스트가 PCIe를 통해 커널 실행을 요청하고 FPGA의 RISC-V 코어와 벡터 유닛이 연산을 수행하도록 연동할 계획임. 보드가 이 요청을 받아 커널을 시작하는 절차와 인자 형식은 드라이버 규격에 맞춰 확정해야 함.
  - PIM 연산에서는 Backend가 뱅크별 데이터 배치에 맞춰 명령 시퀀스를 구성함. 현재 PIM 프로토타입의 외부 호스트는 Xilinx QDMA Linux 드라이버를 사용해 PCIe로 피연산자와 명령을 보드 메모리에 기록하고, 보드의 doorbell 레지스터에 써서 실행을 요청함. FPGA의 dispatcher는 기록된 순서대로 명령을 읽어 뱅크 연산을 시작함. 통합 보드에 적용하려면 Backend가 생성한 명령의 인코딩과 뱅크 주소를 보드 규격에 맞춰야 함.
  - Xilinx QDMA Linux 드라이버 패키지는 호스트의 사용자 공간에서 실행하는 명령행 도구를 제공함. 이 중 `dma-ctl`은 큐 관리 도구로, Linux의 Netlink 인터페이스를 통해 커널 드라이버에 전송 큐의 생성·시작·정지·삭제를 요청함. 데이터 전송 도구인 `dma-to-device`와 `dma-from-device`는 드라이버가 큐별로 제공하는 장치 파일을 사용함. 전자는 장치 파일에 데이터를 써서 호스트에서 보드로 전송하고, 후자는 장치 파일을 읽어 보드에서 호스트로 데이터를 가져옴.
  - 커널 드라이버 내부의 `libqdma`는 전송 큐와 DMA descriptor를 관리하고, FPGA의 QDMA 하드웨어는 해당 descriptor에 따라 PCIe로 데이터를 전송함. 이 경로를 통해 보드에 기록한 명령은 FPGA의 dispatcher가 읽어 실행함. 통합 보드에서 NDP 커널을 시작하거나 PIM 연산 완료를 조회하는 드라이버 인터페이스는 아직 확정되지 않음.
  - 두 엔진 모두 Backend가 런타임에 완료를 알리는 기준은 연산이 끝나고 출력 버퍼의 값을 읽을 수 있는 시점임. PCIe 전송이 끝난 뒤에도 장치에서는 연산이 계속될 수 있으므로, 통합 보드에서 호스트가 연산 완료를 확인하는 방식으로 polling과 인터럽트, 두 방식을 병행하는 방안을 검토 중임.

- **통합 보드의 데이터 공유**
  - 현재 NDP와 PIM은 각각 별도의 VHK158 프로토타입에서 동작함. 통합 CXL-PIM 보드에서 PIM의 연산 결과를 NDP 커널이 같은 버퍼에서 읽으려면, 두 엔진이 해당 버퍼에 접근할 때 사용하는 주소와 NDP가 PIM의 쓰기 결과를 읽을 수 있는 시점을 정의해야 함.
